## 1. 현상

동일한 건적의뢰 건("KEPCO 이진 과장 가스켓")이 칸반 보드의 **Delivery Items(납품진행)** 컬럼에 3개의 개별 카드로 표시되었습니다.

| 카드 | 발신자 | 날짜 | 비고 |
|------|--------|------|------|
| Order #498 | 강동식 (ddtl.co.kr) | 2026-02-24 | 원본 메일 |
| Order #495 | 유종현 (smartvalve.com) | 2026-02-24 | RE: 답장 |
| Order #583 | 유종현 (smartvalve.com) | 2026-03-06 | RE: 후속 답장 |

클라이언트 관점에서 이 3건은 하나의 거래로, 단일 카드로 관리되어야 합니다.

## 2. 원인 분석

### 근본 원인: 이메일 스레드 연결 로직의 한계

CPOFlow의 이메일 수신 파이프라인은 **RFQ 관리번호(reference_no)** 기반으로 동일 건을 식별하여 하나의 카드로 통합합니다.

그러나 이 건은 한국어 내부 이메일로, 제목에 RFQ 번호(예: `6000009486`)가 포함되지 않았습니다. 따라서 시스템이 동일 건으로 인식하지 못하고 3개의 독립 카드를 생성했습니다.

**기술 상세:**
- 3개 Order 모두 동일한 Gmail 스레드 ID (`19c89810c2bd6c58`)를 공유
- 그러나 `reference_no`가 비어있어 부모-자식 연결(`parent_order_id`) 실패
- `find_parent_order` 메서드가 `reference_no`가 비어있으면 즉시 `nil`을 반환하여 fallback 없이 새 카드 생성

## 3. 조치 내용

### 즉시 조치 (2026-03-25 적용)

**Gmail 스레드 ID 기반 자동 연결 로직 추가**

기존에는 `reference_no`만으로 동일 건을 판별했으나, 이제 `reference_no`가 없는 경우에도 **Gmail 스레드 ID**를 기반으로 동일 이메일 스레드의 후속 메일을 자동으로 기존 카드의 하위 카드(sub-order)로 연결합니다.

**수정 전:**
```
이메일 수신 → reference_no 추출 → 없으면 새 카드 생성
```

**수정 후:**
```
이메일 수신 → reference_no 추출 → 없으면 gmail_thread_id로 기존 카드 검색 → 있으면 하위 연결, 없으면 새 카드 생성
```

### 기대 효과

- 동일 이메일 스레드의 후속 메일이 별도 카드로 생성되지 않음
- 한국어 이메일 등 RFQ 번호가 없는 경우에도 스레드 기반 자동 통합
- 기존 RFQ 번호 기반 로직은 그대로 유지 (1순위)

## 4. 현재 건 처리

기존에 생성된 3개 카드 중:
- **Order #498** (원본)을 메인 카드로 유지
- **Order #495, #583**은 수동으로 삭제하거나, 필요 시 #498의 하위 카드로 연결 가능
