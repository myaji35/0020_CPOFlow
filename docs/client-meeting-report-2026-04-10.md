## 안건 1: 메일의 내용 확인이 어려움

### 문제 분석
- 이메일 본문 표시 영역이 `max-h-96` (384px)로 고정되어 긴 메일은 내부 스크롤 필수
- "전체보기/접기" 토글 버튼 없음
- Drawer 내 원본 이메일은 `max-h-48` (192px)로 더 작음

### 조치 내용
- **inbox/show.html.erb**: `max-h-96` → `max-h-[600px]` 확대 + "전체보기/접기" 토글 버튼 추가
- **_drawer_content.html.erb**: `max-h-48` → `max-h-80` 확대 + 펼치기 버튼 추가
- 토글 클릭 시 `max-h-none`으로 전환하여 전체 본문 표시
- HTML 이메일 / Plain text 이메일 모두 동일 적용

### 조치 결과
- ✅ 이메일 본문 표시 영역 56% 확대 (384px → 600px)
- ✅ "전체보기" 버튼으로 제한 없이 전체 본문 확인 가능
- ✅ Drawer 내 원본 이메일도 확대 (192px → 320px) + 토글 추가

## 안건 2: 검색 및 검색 결과 선택이 어려움

### 문제 분석
- Inbox 검색: 제목/발신자/고객명만 검색 → 이메일 본문 검색 미지원
- SearchController: Order 제목/고객명만 검색 → 이메일 관련 필드 미포함
- 검색 결과에 카테고리 구분자 없음, 결과 간 시각적 구분 부족

### 조치 내용
- **inbox_controller.rb**: `original_email_body` LIKE 검색 추가 (본문 검색 지원)
- **search_controller.rb**: `original_email_subject`, `original_email_from` 검색 필드 추가
- Order 검색 시 제목 없는 이메일도 `original_email_subject`로 표시

### 조치 결과
- ✅ Inbox 검색에 이메일 본문 내용 검색 추가 완료
- ✅ 통합 검색에 이메일 제목/발신자 검색 추가 완료
- ✅ 제목 없는 Order도 이메일 제목으로 검색 결과에 표시

## 안건 3: 첨부파일 업로드 안됨

### 문제 분석
- `OrdersController#attach`: `files.blank?` 체크만 수행, 구체적 에러 메시지 없음
- 클라이언트 측 파일 크기/타입 검증 없음
- 업로드 실패 시 사용자에게 원인 표시 안 됨
- 파일 첨부 후 리다이렉트 대신 Turbo 처리 → 화면 깜빡임으로 업로드 실패로 오인 가능

### 조치 내용
- **orders_controller.rb**: 파일 크기 서버 검증 (25MB 제한) + 구체적 에러 메시지 반환 + JSON 응답 지원
- **_drawer_content.html.erb**: 클라이언트 측 파일 크기 검증 (25MB) + 초과 시 빨간색 경고 메시지
- respond_to로 HTML/JSON 양쪽 응답 지원

### 조치 결과
- ✅ 서버 측 25MB 파일 크기 제한 + 초과 파일명/크기 명시 에러
- ✅ 클라이언트 측 즉시 크기 검증 — 초과 시 빨간색 경고 + 파일 선택 초기화
- ✅ 빈 파일 선택 시 alert → redirect_back으로 자연스러운 UX

## 안건 4: AIRBA 시스템에서 자동 파일을 찾고 업로드된 메일 없음

### 문제 분석
- `AribaFetchJob` → `AribaScraperService` → Playwright 브라우저 자동화 체인
- **핵심 실패 원인**:
  1. Ariba 링크 감지 정규식(`ARIBA_LINK_PATTERN`)이 HTML 인코딩된 URL 미처리
  2. Playwright Node.js 런타임이 배포 서버에 미설치일 수 있음
  3. Ariba 2-step 로그인 변경 시 자동 로그인 실패
  4. 재시도 2회만 허용 (네트워크 불안정 시 부족)

### 조치 내용 (분석 + 로그 강화)
- **ariba_fetch_job.rb**: 재시도 횟수 2→3회로 증가, Activity 기록 추가 (성공/실패 모두)
- **ariba_scraper_service.rb**: HTML 엔티티 디코딩은 이미 구현되어 있음 확인 (L52 `CGI.unescapeHTML`)
- ⚠️ **완전 해결 불가**: Playwright 환경 + Ariba 로그인 안정화는 인프라 작업 필요

### 조치 결과
- ✅ 재시도 3회로 증가 — 일시적 네트워크 문제 대응 강화
- ✅ Ariba 문서 수집 성공/실패 시 Activity에 기록 → 히스토리 탭에서 확인 가능
- ⚠️ 근본 해결: Playwright 배포 서버 설치 + Ariba 로그인 모니터링 필요 (중기 과제)

## 안건 5: 채팅에서 담당자 설정 안됨

### 문제 분석
- 댓글(Comment)과 담당자 배정(Assignment)이 완전 분리된 별도 시스템
- 코멘트 탭에 담당자 배정 UI 없음
- @멘션은 알림만 발송, 자동 배정 미연동
- 배정 변경 Activity 기록 없음

### 조치 내용
- **_drawer_content.html.erb**: 코멘트 탭 상단에 담당자 빠른 배정 UI 추가 (배정됨/미배정 구분 표시)
- **assignments_controller.rb**: 담당자 추가/제거 시 Activity 기록 추가
- 코멘트 탭에서 현재 담당자 아바타 표시 + "담당자 배정" 버튼 노출

### 조치 결과
- ✅ 코멘트 탭 상단에 담당자 빠른 배정 패널 추가 — 배정/미배정 직원 구분
- ✅ 담당자 변경 시 Activity 기록 (히스토리 탭에서 추적 가능)
- ✅ 이미 배정된 직원은 "배정됨" 표시로 중복 배정 방지
