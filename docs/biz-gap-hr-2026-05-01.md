## 2. 도메인 모델 요약

| 모델 | 핵심 필드 | 주요 관계 | 주요 스코프/메서드 |
|---|---|---|---|
| `Employee` | name, name_en, nationality, passport_number, employment_type(regular/contract/dispatch), hire_date, termination_date, active, email, department_id, job_title, user_id | has_many visas, employment_contracts, employee_assignments, certifications; belongs_to department, user | `active`, `by_name`, `dispatched`; `visa_expiring_soon?`(60일), `contract_expiring_soon?`(30일), `tenure_label` |
| `Visa` | visa_type(Employment/Tourist/Transit/Residence), issuing_country, expiry_date, status(active/expired/pending/cancelled), renewal_started_at, renewal_status, renewal_note | belongs_to employee | `expiring_within(days)`, `expiry_urgency`(:critical≤14/:warning≤30/:caution≤60), `days_until_expiry` |
| `EmploymentContract` | start_date, end_date, base_salary, currency(AED/USD/KRW/EUR), pay_frequency(monthly/bi-monthly/weekly), status(active/expired/terminated/renewed), project_id | belongs_to employee, project | `active`, `expiring_within(days)` |
| `EmployeeAssignment` | start_date, end_date, role, status(active/completed/cancelled), project_id | belongs_to employee, project | `active`, `by_start` |
| `Certification` | name, issuing_body, issued_date, expiry_date | belongs_to employee | `by_expiry`, `expiring_within(days)`, `expired?`, `expiring_soon?`(30일 이내) |
| `Department` | name, sort_order, active, parent_id, company_id | belongs_to company, parent; has_many employees, sub_departments | `active`, `root_level`, `full_name` (계층 표시) |
| `Company` | name, company_type(hq/branch/site_office), country_id, active | has_many departments, employees(through dept) | `active` |
| `JobTitle` | name, sort_order, active | 독립 참조 테이블 (Employee.job_title은 문자열 저장) | `active`, `by_sort` |
| `User` | email, name, role(viewer/member/manager/admin), branch(abu_dhabi/seoul), notification_preferences | has_one employee | `notify_on?(type, channel)`, `visa_expiring` 알림 타입 등록됨 |

**알림 타입 정의** (`User::NOTIFICATION_TYPES`): `rfq_new`, `order_overdue`, `order_assigned`, **`visa_expiring`**(default:true), `ecount_conflict`, `kpi_weekly`

## 6. AtoZ2010 특화 리스크

### UAE 거주 외국인 직원 多 → 비자/거주증 관리 최우선

| 리스크 | 현재 상태 | 결과 |
|---|---|---|
| Employment Visa 만료 → 불법 체류 | D-60/D-30/D-14 알림 있음. 갱신 시작 마킹 존재. **자격증 만료는 미감지** | 비자는 PARTIAL COVERAGE, 자격증은 MISSING |
| 비자 갱신 완료 확인 | `renewal_status` 컬럼 있으나 **"갱신 완료" 상태 전환 UI 없음** (`start_renewal` 액션만 있고 `complete_renewal` 없음) | 갱신 완료 추적 불가 |
| 여권 만료 추적 | `passport_number` 컬럼 존재. **여권 만료일 컬럼 없음** | 여권 만료 자동 감지 불가 |

### Abu Dhabi / Seoul 이중 법인 → branch별 정책 차이

| 리스크 | 현재 상태 |
|---|---|
| 지점별 노동법 차이 (UAE vs 한국) | Employee는 branch 컬럼 없음 (User에만 있음). Department → Company → Country로 간접 추론 필요 |
| 지점별 HR 담당자 권한 분리 | manager 역할이 전 지점 직원 데이터 접근 가능 — 지점별 데이터 격리 없음 |
| 서울 지점 직원의 비자 불필요 | Visa 필수 여부 지점별 로직 없음 — 서울 직원에게도 비자 등록 CTA 표시됨 |

### 계약직/파견 혼합 → 고용형태별 워크플로우 차이

| 리스크 | 현재 상태 |
|---|---|
| 파견(dispatch) 직원은 EmployeeAssignment가 핵심 | CRUD 있음. **파견 기간 만료 알림 없음** |
| 계약직(contract) 갱신/종료 자동 워크플로우 | 계약 만료 알림은 있음. **갱신 또는 종료 의사결정 워크플로우 없음** |
