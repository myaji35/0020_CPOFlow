### C-1. Branch 격리 완전 미적용 — inbox AI 액션 5개 엔드포인트

**영향 받는 저니:** 구매담당자(member) — RFQ 분류 / 답변 초안 생성  
**현재 상태:** `inbox#show`, `inbox#translate`, `inbox#reclassify`, `inbox#feedback`, `inbox#generate_reply` 모두 `Order.find(params[:id])` 직접 호출.

```

app/controllers/inbox_controller.rb:253  order = Order.find(params[:id])
app/controllers/inbox_controller.rb:281  order = Order.find(params[:id])
app/controllers/inbox_controller.rb:337  order = Order.find(params[:id])
```

**위험도:** seoul 사용자가 abu_dhabi 이메일 ID를 추측하면 번역/피드백/초안 생성이 가능. AI API 비용도 타 브랜치 이메일에 소비.  
**권장 수정:** 위 5개 메서드의 `Order.find` → `scoped_orders.find` 또는 `scoped_orders.find_by!(id: params[:id])` 교체.

### M-5. orders#price_history — Branch 격리 없음 + 입력값 SQL LIKE injection 가능성

**현재 상태:** `Order.where.not(estimated_value: [nil, 0])` unscoped 호출. `params[:item_name]`을 `LIKE ?` 파라미터로 사용 시 사용자가 `%` 패딩으로 모든 오더 매칭 가능.  
**코드 증거:**
```
app/controllers/orders_controller.rb:155  scope = Order.where.not(estimated_value: [nil, 0])
app/controllers/orders_controller.rb:160  scope = scope.where("item_name LIKE ?", item_like)
```
**위험도 1:** 타 브랜치 단가 이력이 폼 자동완성에 노출.  
**위험도 2:** LIKE `%` 패딩은 바인딩 파라미터로 처리되므로 SQL 인젝션은 아니나, 과도한 데이터 노출 가능.  
**권장 수정:** `scoped_orders` 적용.

## MINOR 갭

### N-1. 온보딩 3단계 완료 정의의 논리적 오류

**현재 상태:** `user#onboarded?`가 `gmail_connected? && has_created_order? && has_assignment?` 3가지 조건을 모두 요구. 그러나 구매담당자가 Gmail 연결 없이도 업무 가능하며, 관리자는 Gmail 연결이 필요 없을 수 있음.  
**코드 증거:**
```
app/models/user.rb:139  def onboarded? = gmail_connected? && has_created_order? && has_assignment?
```
**영향:** Gmail 연결을 원하지 않는 사용자에게 온보딩 미완료 배너가 영구 표시.

### N-2. Assignment uniqueness — SQLite NULL 중복 허용 위험

**현재 상태:** `assignments` 테이블에 `(order_id, employee_id)` unique index가 있으나 SQLite는 NULL에 대해 여러 NULL 값을 허용. `employee_id: nil`인 user 기반 배정이 중복 가능.  
**코드 증거:**
```
db/schema.rb:112  t.index ["order_id", "employee_id"], unique: true
app/models/assignment.rb:2   belongs_to :employee, optional: true
```

---

### N-3. 칸반 모바일 뷰 — 9개 컬럼 가로 스크롤 UX 미흡

**현재 상태:** `overflow-x-auto`로 가로 스크롤은 가능하나 모바일에서 9개 컬럼의 카드 밀도가 높음. 스와이프 제스처로 컬럼 이동 불가.  
**배포 사이트 확인:** `<html lang="en">` + `viewport` 메타 정상. 기본 반응형 설정은 있으나 칸반 모바일 레이아웃 최적화 없음.

### N-4. 리포트 CSV 수출 시 branch 필터 미반영

**현재 상태:** `reports#export_csv`가 `report_scoped_orders`를 호출하나, `@selected_branch`가 `export_csv` 액션에서 초기화되지 않아 branch drill-down 필터가 CSV에 반영되지 않을 수 있음.  
**코드 증거:**
```
app/controllers/reports_controller.rb:52-68  export_csv -- @selected_branch 사용 있으나 params 파싱 확인 필요
```

---

### N-5. reviews#new/create — 인증 없이 접근 가능 (의도적이지만 명문화 필요)

**현재 상태:** `ReviewsController`의 `new/create`는 `authenticate_user!`가 적용되지 않은 public 엔드포인트. 스팸 피드백 제출 위험.  
**코드 증거:**
```
config/routes.rb:199  resources :reviews, only: %i[new create]  -- 공개 접근
```
**권장 수정:** Rate limiting 또는 reCAPTCHA 추가.

---

### N-6. 일일 알림 Job 시간대 미고려 — 배포 서버 UTC 기준

**현재 상태:** `DueNotificationJob` 스케줄이 `every day at 7am`인데, 배포 서버가 UTC 기준이면 UAE(UTC+4) 사용자에게는 11:00에 도착.  
**권장 수정:** `every day at 3am UTC` (UAE 07:00) 또는 `config.time_zone` 설정 검토.

---

### N-7. 아카이브된 오더 복구 UI 없음

**현재 상태:** `Order#archive!`와 `archived_at` soft-delete 구현이 있으나, 아카이브된 오더를 복구(unarchive)하는 UI 경로가 없음.  
**코드 증거:**
```
app/models/order.rb:81  def archive! = update!(archived_at: Time.current)
app/models/order.rb:76  scope :archived, -> { where.not(archived_at: nil) }
```
관리자 라우트에 아카이브 복구 경로 없음.

---

### N-8. 캘린더(/calendar) — Branch 격리 확인 필요

**현재 상태:** `CalendarController`의 scope 확인이 필요하나 `scoped_orders` 사용 여부 미확인.  
**권장 수정:** `calendar_controller.rb` 내 모든 Order 조회에 `scoped_orders` 적용 확인.
